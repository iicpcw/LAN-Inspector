# 内网巡检台

Windows 离线桌面工具，仅依赖 Python 标准库，无需 pip、互联网或 API 密钥。请在获得授权的网络中使用。

## 启动与使用

1. 安装带 Tcl/Tk 的 Python 3（Windows 官方安装包通常自带），双击 start.bat，或执行 python lan_inspector.py。
2. 默认目标为本机 127.0.0.1。填写 IP 或 CIDR，例如 192.168.1.0/24；多个目标用空格或逗号分隔，单次最多 1024 个地址。
3. 填写端口，例如 22,80,443,8000-8100。取消“扫描 TCP”时只做 ICMP / ARP 主机发现。
4. 点击开始，可随时停止。导出支持 CSV（Excel 可打开）和 JSON；扫描中导出为当前已有结果。

## 能力及边界

- IP 发现通过主动 ICMP、TCP、ARP 探测完成。本版本不包含被动流量抓包。
- ICMP 被屏蔽时仍检测所选 TCP 端口。仅目标 ICMP 回应或 TCP 连接成功计为在线。ARP 返回 MAC 时单独标为“仅 ARP 响应”，不计入在线数量。
- “未确认”不代表离线，丢包、防火墙或超时均可能影响结果。
- TCP 为完整连接扫描，仅显示连接成功的端口，不区分关闭与过滤。不包含 UDP；1.2 支持有限的 SSH 和 HTTP/HTTPS 指纹采集。
- MAC 通过 Windows SendARP 获取，通常仅适用于同一二层链路。跨路由/VLAN 隔离无法直接获取；代理 ARP 可能返回代理设备 MAC。
- 并发针对主机，每台的端口顺序检测。单台最坏耗时约为端口数乘超时，加 ICMP / ARP 耗时。停止后需等待当前系统调用结束。
- 推荐 Windows。其他系统可尝试 ICMP/TCP，但本版本不实现其他系统的 MAC 查询。
- 导出字段：ip、status、mac、ports、evidence、scan、attempted（TCP 尝试数）。

## 内网部署

携带整个目录及 Python 离线安装包进入内网，安装 Python 后启动即可。交付为源码工具，不含 Python 运行时或 EXE，无第三方依赖。

## 1.1 修复

修正仅凭 ARP 返回 MAC 就认定在线的误报。多个 IP 共用 MAC 时提示可能为代理 ARP；该提示也可能出现在合法多 IP 设备上。ICMP 必须匹配目标 IP 和带 TTL 的响应行，不接受不可达消息。导出新增 warning 字段。仅 ARP 响应也可能是真实设备，但需要进一步核实。TCP 代理或响应 ICMP 的网络设备仍可能影响判定，在线状态表示观察到探测响应。


## 1.2 设备识别与拓扑图

### 设备识别

默认启用“识别设备”，对已扫描发现开放的 22、80、443、8000、8080、8443 端口读取少量服务响应。默认端口列表包含这些端口；自定义时未包含的端口不会额外探测。关闭 TCP 扫描也就无法采集这些指纹。

- 根据管理页面或 SSH 中的产品字符串推测防火墙、交换机、路由器、Windows 或 Linux 终端/服务器。
- 当前覆盖部分 FortiGate/FortiOS、PAN-OS、Sophos、SonicWall、pfSense/OPNsense、Cisco ASA、Catalyst、ProCurve、ArubaOS-Switch、部分 Huawei/H3C 交换机型号、RouterOS、OpenWrt、VyOS、EdgeOS、IIS/Windows OpenSSH、Ubuntu/Debian 等字符串。
- 产品/系统字符串匹配为中等置信度；端口组合判断为低置信度。不会根据 SSH、nginx 或 Apache 单独认定 Linux，也不会把所有未知网络设备猜成交换机。
- 多类指纹冲突时标记“类型待核实”。识别的是暴露的服务特征，代理、自定义页面、容器或伪造 Banner 都可能影响结果，不能保证硬件型号或终端/服务器角色正确。
- 不尝试口令、登录、漏洞利用或遍历页面。每个服务最多一次连接，HTTP 仅请求根路径、不跟随跳转；单次读取最多 8192 字节，SSH 最多 2048 字节。响应分片或页面无产品信息时可能无法识别。
- HTTPS 采集允许自签名证书，不发送凭证，不能用于验证设备身份。
- 识别列在结果表右侧，可使用底部横向滚动条查看；双击一行可查看完整字段及服务内容。
- CSV / JSON 增加 device_type、confidence、fingerprint、service_banners 字段。导出服务响应前可检查其中是否有内部敏感信息。

### 自动生成拓扑

正常扫描结束后，自动在程序目录的 reports 文件夹生成带时间戳的 HTML 图，点击“打开拓扑图”用本机浏览器查看。无外部字体、脚本或 CDN，完全离线可用；可通过浏览器打印到 PDF。停止扫描后，也可点击按钮生成已完成部分的图。

图按输入的网段进行分组；输入单个 IP 则归入对应 /32 组。重叠网段采用最具体的输入网段。绿色节点代表观察到 ICMP/TCP 响应，棕色代表仅 ARP 响应。无响应地址不画成设备，只列在明细表中。鼠标悬停节点可查看完整依据。

**这是网段逻辑归属图，不是物理拓扑或实测路由拓扑。** 虚线表示设备 IP 属于哪个扫描网段，不表示接在某台交换机上。本版本未采集 SNMP、LLDP/CDP、交换机 MAC 转发表和路由表，因此无法可靠还原交换机端口、上下联、防火墙/路由器之间的实际连线。即便识别为交换机，也不会把其他主机随意连到它上面。

### 验证记录

通过原有 6 项回归测试，以及新增 7 项设备识别、冲突处理、保守判定、取消、HTML 转义、逻辑图分组和扫描结束自动生成测试。网络响应采用模拟数据；当前开发环境阻止真实套接字连接，未对实际品牌设备做实网认证。

## 1.3 内网封堵规则检查

按用户指定的内网管理规则，默认将 TCP 22、80、135、443 列为要求封堵的端口。可在“要求封堵的 TCP 端口”中添加或修改，例如 21,22,23,80,135,139,443,445,3389；留空表示不配置该项规则。这里的“高危”是本次内网管理规则的标签，不代表这些端口在所有环境中均应关闭或存在已验证漏洞。

启用 TCP 扫描时，实际检测端口为“TCP 端口”与“要求封堵的 TCP 端口”的并集，避免遗漏检查项。关闭 TCP 扫描不会额外扫描，规则检查显示不完整。

- 配置端口 TCP 连接成功：显示“常见高危端口未封堵”，列出命中的端口号及常见服务名，结果行标红；服务名按惯例显示，不表示已验证该端口上运行的服务。
- 没有连接成功且检查已执行：显示“未发现策略端口可连接”。超时、不可达或拒绝连接均不能证明已经配置封堵措施。
- 未覆盖规则端口、取消或本机权限/套接字异常：显示检查不完整或在检查详情列明未完成的端口。已发现的开放端口仍保持告警。
- 双击设备行可查看 audit_detail；CSV/JSON 导出增加 audit_status、risk_ports、audit_detail、policy_ports、unchecked_policy_ports，保留本次规则快照。
- 拓扑图中命中规则的节点以红色边框突出显示，节点列出未封堵端口，明细表显示检查结果及规则；完成提示统计告警设备数。

示例：目标 TCP 22 和 443 可连接时，报告“常见高危端口未封堵：TCP 22 (SSH), TCP 443 (HTTPS)；违反本次配置的内网封堵规则”。工具只检测和报告，不修改目标防火墙或关闭服务。

本次新增 7 项测试，覆盖默认端口、自定义规则、未扫描/取消、异常、模拟开放端口、界面红色告警及 HTML 明细一致性；原有 13 项测试仍通过。真实网络效果需在部署环境复测。

## 1.4 移动设备线索与离线 MAC 厂商库

### 支持什么

新增“MAC 注册厂商”“设备推测与限制”“MAC 属性”列。双击结果查看完整厂商匹配前缀、依据；CSV/JSON 和拓扑报告同步增加 mac_vendor、mac_scope、vendor_prefix、vendor_evidence、device_hint 字段。厂商查询独立于端口指纹开关，取得 MAC 后即可离线匹配。

内置 IEEE 公开注册库的 MA-L、MA-M、MA-S、IAB 地址段，共 58,903 条（下载于 2026-10-29）。按 36/28/24 位最长前缀优先匹配，支持 Apple、Samsung、小米、华为等组织及其他登记组织。厂商库仅包含前缀、注册类别、注册组织，不含组织通信地址。来源、原始条目数与 SHA-256 见 mac-vendors-source.json。运行时不访问厂商查询网站，也不向互联网发送扫描到的 MAC。

- Apple 注册前缀：提示可能为 iPhone/iPad/Mac/其他产品，不能仅由此确定 iOS。
- Samsung、小米等：可能为手机、平板、电视或 IoT，不能仅由此确定 Android。
- Intel、Realtek 等芯片/网卡组织：提示网卡厂商不等于整机品牌。
- 本地管理位被置位：显示“本地管理地址（可能为随机/私有 MAC）”，跳过厂商推测。该特征也可能来自手动配置、虚拟机等，不能直接认定为手机。
- 多个 IP 共用相同 MAC：保留该地址段注册组织，但提示可能属于代理或网关，不能据此归属终端品牌。
- 未获取 MAC 或厂商库没有匹配：明确显示未知，不猜测品牌。

如果采集到的 SSH/Web 响应包含明确 iPhone OS、iPad CPU OS、Apple Mobile Device 或 Android 字符串，显示“疑似 iOS/iPadOS 移动设备”或“疑似 Android 设备”，置信度为低，仍可能来自代理、管理页面或自定义内容。不会把 Cisco IOS 当成 Apple iOS。无开放服务的手机只能显示 MAC 相关线索；睡眠、无线隔离或跨路由可能使手机无法被发现。

### 识别边界

MAC 前缀表示地址段注册组织，不是系统检测，更不能保证品牌、具体型号或手机身份。iOS/Android 都可能使用私有/随机 MAC，电脑也可能使用这种地址；对这类地址不能进行可靠的厂商推测。全局管理 MAC 也可能被修改。要准确区分已纳管移动设备，需要结合无线控制器、DHCP、MDM 或终端资产信息；本版本尚未接入这些数据。

### 厂商库维护

内网部署时务必携带 mac-vendors.csv。它是离线快照，不会自动更新；更新可在可联网电脑上准备同格式 CSV（prefix,registry,organization，前缀为 6/7/9 个十六进制字符），替换后重启工具。库缺失或损坏时显示原因，不影响基础扫描。

官方参考：

- IEEE 注册库入口：https://standards.ieee.org/products-programs/regauth/
- Apple 私有 Wi-Fi 地址：https://support.apple.com/en-nz/102509
- Android MAC 随机化：https://source.android.com/docs/core/connect/wifi-mac-randomization

### 验证

新增 9 项测试覆盖地址段最长匹配、真实离线库、随机 MAC、无效/组播地址、Apple 品牌与系统区分、共享 MAC、移动服务指纹、报告及界面。此前 20 项测试仍通过。尚未在真实 iPhone/Android 设备上验证识别效果。

## 1.5 本机 Windows 端口管理与勾选封堵

### 使用方式

1. 启动工具，点击“本机端口管理”；也可直接双击 start-local.bat。
2. 点击“扫描 / 刷新”，列出本机 TCP 监听端口、UDP 绑定端口、IPv4/IPv6 绑定地址、PID 和进程名。此功能枚举操作系统端口表，不会对其他主机发起扫描，也不会只检查常见端口。
3. 点击表格第一列的方框勾选，或选中行后按空格。可勾选全部或清空。
4. 点击“封堵勾选端口”。如果当前不是管理员，请点击“以管理员身份重新打开”，接受 Windows UAC 提示后，在新窗口重新扫描、勾选。
5. 程序展示所选协议/端口及生效范围，确认后批量添加 Windows 防火墙规则，并逐项显示结果。
6. 要恢复访问，切换到“本工具规则（可撤销）”，勾选要删除的规则，点击“撤销勾选的本工具规则”。监听进程即使已退出，对应规则仍可撤销。

### 封堵范围及结果含义

- 支持 Windows 10/11 及提供 NetTCPIP、NetSecurity 模块的 Windows Server，需要系统内置 Windows PowerShell。读取端口优先用 Get-NetTCPConnection / Get-NetUDPEndpoint；CIM 查询失败时回退到 netstat -ano，并显示原因。
- 封堵通过创建持久的 Windows 防火墙入站 Block 规则完成：按 TCP/UDP + 本地端口，全本机地址、全部网络配置文件、所有进程。IPv4/IPv6 相同协议和端口会合并成一条规则。
- **封堵网络访问不等于停止服务。** 程序不会杀进程、禁用服务或修改应用配置；封堵后重新扫描仍能看到监听端口，这是正常现象。
- 监听/绑定端口不等于网络上可访问。UDP 绑定尤其不能说明 UDP 服务对远端开放。本机回环连接也不能可靠验证外部访问是否被阻断，应从另一台授权内网主机复测。
- 显示规则创建和读回结果，不将“规则存在”当作“已实测封堵”。界面同时列出规则在 ActiveStore 的可见性及各防火墙配置文件状态。防火墙未启用、组织策略禁止本地规则合并或其他管理产品可能影响生效；程序不会修改这些全局设置。
- 封堵远程桌面、SSH、WinRM、RPC、共享等端口可能中断管理或业务访问。确认框对常见远程管理端口额外提示，建议在可本地恢复的情况下操作。
- 操作逐项返回成功/失败。发生超时，结果显示“未确认”，因为部分规则可能已经写入；请刷新规则表核实。操作进行中不允许关闭窗口，以便保留结果反馈。

### 规则归属与撤销

规则组：LAN Inspector Local Port Blocks v1

规则名格式：LANInspector.LocalPortBlock.v1.TCP.80（UDP 同理）

仅操作固定命名且属于本工具规则组的规则，不批量删除系统或他人规则。同名非本工具规则会拒绝操作；已存在的本工具规则不会被静默扩大范围或覆盖。撤销只删除本工具对应规则，不额外添加允许规则，也不保证端口之后一定可访问。也可在 Windows 高级安全防火墙中按上述组和名称找到对应规则进行管理。

### 本地报告与验证

每次刷新或操作完成，会在 reports 目录保存 local-ports-时间戳.json，包含监听表、进程、规则、防火墙状态和本次逐项处理结果。仅保存在本机。

新增 10 项测试，覆盖输入限制、端口去重、非管理员拒绝修改、结构化 PowerShell 参数、空选择、取消确认、超时、错误反馈、勾选封堵/撤销范围及操作中关闭保护。原有 29 项测试通过，PowerShell 脚本语法检查通过。开发环境的只读运行验证了 CIM 受限时回退 netstat 的流程；该隔离环境未返回监听端口，防火墙状态查询也受限。未在开发电脑实际创建或删除防火墙规则，因此需要在目标 Windows 环境验证规则的实际网络效果。

## 1.6 动态、多网段、可编辑资产拓扑

### 启动与扫描

双击 start.bat 现在默认打开程序内的动态拓扑视图。程序先载入上次保存的资产，再通过本机活动网卡的真实 IPv4 地址和掩码识别本机网段，自动扫描默认网段。存在多个活动网卡时会显示各网卡所在的逻辑网段；默认扫描优先采用有网关的网卡，输入框可自行修改。

输入框支持任意完整、可达的 IPv4/CIDR 网段，也支持用空格或逗号填写多个网段：

192.168.192.0/24 192.168.4.0/24

“192.0/24”“4.0/24”是缩写，不能直接使用；请按实际地址写完整，示例并不表示自动推断你的前缀。工具按输入扫描，不会自动扩展到所有可路由网段。每轮合计最多 1024 个地址；更大的网段需分批扫描。识别到本机为 /16 等大网段时会显示该网段，但要求缩小扫描范围，不会自动猜成 /24。

默认勾选“完成后每 60 秒刷新”。每轮完成并等待 60 秒后刷新当前输入的目标，扫描期间不重叠启动。取消勾选可关闭定时刷新；点击停止会结束当前轮，之后不会自动重启，手动再次扫描即可恢复。

原有扫描表格和 HTML 报告仍可在“高级扫描 / HTML 报告”打开，“本机端口与防火墙”继续提供本机端口和封堵功能。

### 图上展示与交互

设备卡片显示名称、类别、IP、MAC、状态、MAC 注册厂商及最近检查时间。单击设备在右侧查看详细信息；拖动设备卡片可移动位置，布局会保存；滚轮上下滚动，Ctrl+滚轮或按钮缩放，底部滚动条可平移。“自动布局”按逻辑网段重新排列。

名称优先级：手工名称 > 本机网卡名称（本机节点）/反向 DNS 返回的名称 > IP。DNS 记录可能过时，不作为身份认证；无法取得名称时不伪造名称。设备类别保留之前的服务指纹识别，手工填写的类别优先。

绿色表示本轮 ICMP/TCP 确认在线；棕色为仅 ARP 响应；灰色为未检测、未确认、历史待刷新或手工离线。命中端口封堵规则的设备边框为红色，详情保留具体告警。图中虚线仅表示 IP 资产属于对应网段，不表示真实交换机端口、物理连线或路由路径。

### 手动添加、编辑与保存

- 点击“添加设备”，填入完整 IP、名称、类别、MAC（可空）、所属完整 CIDR 和备注。未扫描到、离线或计划纳管的设备都可添加。
- 选中设备后“编辑选中”或双击卡片。手工名称、类别、MAC、备注与扫描观测分开保存；后续扫描不会覆盖手工字段。
- 状态可选择“自动”“离线（手工）”“停用（手工）”。人工状态会显式标记来源；即便探测有响应，右侧仍保留真实扫描观测以供核实。
- 未响应地址不会自动画成设备。已有设备再次未响应时保留在图上，显示“未确认”或“未确认（曾在线）”，不会直接认定离线或删除。
- 每轮扫描完成、设备修改、拖动或自动布局后自动保存；也可点击“保存”。默认文件为程序目录下 data/inventory.json，包含多网段资产、手工字段、扫描观测、布局和最近目标输入。

- 删除资产后，若后续扫描再次发现同一 IP，会重新加入；IP 是当前资产去重键，DHCP 地址变化暂不自动合并成同一台物理设备。

### 跨网段能力与边界

只要本机到目标网段有有效路由，且中间策略允许相应探测，就可以以相同方式扫描、编辑和保存。目标网段不必与本机相同；多个网段同时展示并分组。

对不在已确认本机直连网段内的目标，动态拓扑不调用 ARP 获取远端 MAC，不会把网关 MAC 作为远端终端的 MAC。跨路由时通常显示“未获取”，可手工补录。没有路由、被 ACL/防火墙过滤或无线隔离的设备可能无法被发现；可手动建立台账，但这不意味着已经确认其在线。

本版本不通过 SNMP/LLDP/CDP、路由跟踪或交换机转发表发现真实链路，因此“跨网段拓扑”是多网段逻辑资产视图，不能据此判断经过了哪台路由器或实际接在哪台交换机上。

### 选中设备测试延时

点击设备，再点击“测试选中设备延时”。后台发起 4 次 ICMP 测试，显示收包数、丢包率和最小/平均/最大往返时延。Windows 的小于 1ms 结果按 0.5ms 估算参与统计，不是亚毫秒精密测量。收到响应可更新在线观测；没有响应只表示未收到 ICMP 回应，不会强行标为离线。结果保存于该资产观测中，右侧详情可查看样本。

## 1.8 网关保留、多网卡选择与独立入口

### 路由器可能没有显示的原因

扫描只能根据 ICMP、选定 TCP 端口、同链路 ARP 的响应发现设备，路由器可能禁止 Ping/管理端口，或其管理地址不在扫描范围。还可能已经发现该 IP，但因没有足够服务指纹而显示未知图标。有虚拟网卡时，默认选中的网段也可能不是目标物理网段。

此前代码已经读取本机网卡配置的网关地址，却没有把这些地址单独纳入资产图，导致没有探测响应的网关被遗漏。本版修正这一点：

- 本机网卡配置中的 IPv4 网关自动加入图中，即使没有探测响应也保留，但状态为未检测/未确认，不计为在线。
- 详情显示来源网卡、该网卡的本地 IP 及配置来源。网关表示路由角色，可能由路由器、防火墙、三层交换机或其他系统提供，不能仅凭角色确定硬件类别。
- 无明确设备指纹的配置网关显示网关图标；检测为防火墙、交换机或用户手工填写类别时保留相应类别。
- 地址超出网卡对应前缀时单独归入其 /32，不伪造网段归属。重新载入的历史网关在当前网卡配置确认前显示为历史配置。
- 增加网卡下拉框，显示名称、本地 IP、网段和网关，可明确选择物理或虚拟网卡。切换后点击扫描/刷新，当前已启动的一轮不会中途改范围。仍支持手动输入其他网段。
- 此修复只能补入本机配置的网关，不能发现所有无响应的路由器，也不能凭本机网关配置推断其他网段的网关；这些设备仍可手工添加。

## 1.9 拓扑子功能：疑似 IP 冲突检测与 ARP 缓存清理

从程序首页进入“动态拓扑”，点击“IP 冲突检测”。检测默认采用拓扑中选中设备的 IP；也可填写所选网卡的直连 CIDR 网段，每轮最多 1024 个地址。选择源网卡后点击开始。

- 每个 IP 采集 3 次 MAC，采集间隔约 0.2 秒，使用所选网卡的源 IPv4 地址，不混用其他网卡的结果。
- 本轮同一 IP 出现多个 MAC，标为“疑似 IP 冲突”。
- 同一源网卡近 10 分钟历史 MAC 与当前不同，标为“IP–MAC 变化，需核实”；这不能证明两台设备同时使用该 IP。
- 网关冗余切换、DHCP 重新分配、网卡更换、代理 ARP 或人为修改 MAC 都可能造成变化，必须结合现场信息核实。
- 仅取得一个 MAC 或无响应时不显示“无冲突”，因为缓存和响应时序均可造成漏检。
- 使用 Windows SendARP/ARP 缓存观测，不是抓包检测，不能保证每次采样都发出新的 ARP 请求。检测本身不自动清除缓存。它不能可靠地收集所有同时响应者，也不支持跨路由判定。
- 可疑节点在拓扑上显示紫色边框和感叹号；点击查看 MAC、源网卡 IP、采集时间和历史。告警、最多 200 条 MAC 观测和 50 条事件随资产文件保存。一次正常采样不会自动清除既有告警；“已核实，清除选中告警”只确认告警，保留历史证据。
- 冲突检测不会把 ARP 响应计为确认在线，也不会自动断网、修改 IP 或封堵设备。

### 清除 ARP 缓存

同一子窗口提供“清除 ARP 缓存…”按钮。先停止扫描和检测，再操作：

1. 选择源网卡，在结果表选中要清理的 IP（可多选）。
2. 点击清除按钮，默认只清这些 IP 的缓存。也可明确选择“所选网卡的全部活动 ARP 缓存”。
3. 核对网卡/IP 和范围，确认后执行。空选择不会默认扩大为全部网卡。
4. 操作需要管理员权限；普通权限下提供 UAC 提权重开拓扑，携带当前资产文件路径。原拓扑保存并关闭，管理员窗口不自动扫描或清理，需要再次手动确认。
5. 命令始终指定网卡索引和 store=active，执行前重新核对网卡索引及本地 IP，避免网卡变化后清错接口。不删除 persistent 存储，也不修改 IP、路由或防火墙规则。
6. 显示逐项执行结果并将清理操作日志保存在资产文件目录的 arp-actions 文件夹。清理不删除冲突检测历史，也不能直接修复重复 IP；访问设备后缓存可能很快重新建立，期间可能短暂影响连接。

- SendARP 与缓存：https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-sendarp
- netsh interface ipv4 delete arpcache：https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/netsh-interface

## 2.1 多来源 MAC 获取与补充按钮

### 获取途径

拓扑扫描和网段扫描增加多来源 MAC 解析，按网卡区分记录：

1. 本机地址直接从对应网卡读取物理地址，避免对本机 IP 做 ARP 时取不到 MAC。
2. 对确认属于直连网段的目标，用明确的源网卡 IPv4 地址调用 SendARP；已确认响应的设备未取到时可再试一次。SendARP 也可能使用系统缓存，不保证每次发送新 ARP。
3. 读取 Windows Get-NetNeighbor IPv4 邻居表，仅接受相同网卡索引的有效 MAC，记录 Reachable/Stale/Permanent 等状态，排除 Incomplete/Unreachable 和无效地址。
4. 使用 arp -a 作为兼容补充，按接口段和网卡索引解析，兼容中文/英文输出。邻居表和 arp 缓存通常来自同一底层记录，不能把它们当成两个独立的在线证据。
5. 有 Windows/SMB 线索、且其他方法仍未获取时，尝试 UDP/137 NetBIOS Node Status 返回的 UNIT_ID。结果标为设备自报，可能不是目标当前网口的 MAC，也可能因服务关闭或策略过滤无法取得。校验响应来源 IP、端口、事务 ID、响应标志和数据长度，不登录、不发送凭证。

每轮扫描前、结束后读取缓存快照；扫描产生流量后新形成的缓存可用于补齐未获取的结果。不会为每个 IP 都启动一次 PowerShell。仅缓存结果显示“仅缓存记录”，NetBIOS 补充显示“仅设备自报 MAC”，不计入确认在线数量。

### 拓扑中的单设备补充

单击设备，然后点击“补充选中 MAC”。后台重新读取当前网卡与缓存，再进行该目标的源网卡 ARP 和必要的 NetBIOS 查询。单独补充 MAC 不会把旧的 Ping/TCP 在线时间刷新成当前时间，结果有独立的 mac_checked_at 时间。

多张物理/虚拟网卡覆盖同一目标时，请在网卡列表明确选择来源。无法确定来源时不从其他接口随意挑选缓存。跨路由目标仍不直接查询 ARP，也不把网关 MAC 填成远端终端 MAC。

### 来源与不一致处理

结果/详情/CSV/JSON/HTML 新增 mac_source、mac_interface、mac_state、mac_confidence、mac_candidates、mac_errors、mac_note、mac_checked_at。

主动解析和缓存不同，会保留双方候选并提示核实；仅缓存来源之间矛盾时不自动挑一个值。缓存过期、DHCP 地址变化、代理 ARP 都可能产生这种情况，不直接判定为 IP 冲突。历史缓存和设备自报均不保证当前在线或设备身份。零 MAC、广播和组播 MAC 均会过滤，随机/本地管理 MAC 保留原有厂商推测限制。

无响应、无线客户端隔离、VLAN/路由隔离、NetBIOS 关闭等情况仍可能取不到。跨网段如需准确 MAC，通常需查询该网段网关/交换机的邻居表或资产系统；本版本未连接这些系统。

官方参考：
- https://learn.microsoft.com/powershell/module/nettcpip/get-netneighbor
- https://www.rfc-editor.org/info/rfc1002/

### 验证

新增 12 项测试覆盖本机 MAC、源网卡与重试、缓存不等于在线、错误接口/跨网段拒绝、重叠网卡选择、来源矛盾、中文 ARP 输出、NBSTAT 事务/报文/来源验证、设备自报和取消；累计 100 项功能测试通过。开发环境只读验证读到 4 个活动 IPv4 接口、其中 3 个具有有效 MAC，邻居表权限受限时成功走兼容读取流程；未主动扫描真实网段，未执行缓存清理或防火墙修改。实际获取成功率需在部署环境验证。

## 2.2 企业网络设备指纹扩展

本次重点补充华为、华三、中兴和深信服的服务标识、管理页标题及产品族线索，不再只靠家用路由器特征。新增企业指纹模块 enterprise_fingerprints.py，仍为离线运行，不查询互联网或登录设备。

### 已加入的规则范围

- 华为：AR / 部分 NetEngine、NE 系列路由线索，S / CE 系列交换线索，USG 系列防火墙线索。
- 华三 H3C：MSR 系列路由线索，S 系列交换线索，SecPath F 系列防火墙线索。
- 中兴 ZTE：区分 ZXR10 M6000、T8000、ZSR 等路由产品族与 ZXR10 9900、8900、5960 等交换产品族。ZXR10 这个名称本身同时用于不同产品，只有名称不足以分类。
- 深信服：NGAF / AF / NGFW 防火墙线索，上网行为管理线索，EasyConnect / SSL VPN 网关线索及 aTrust 零信任访问网关线索。VPN、上网行为和零信任设备采用安全网关图标，不统一按路由器绘制。
- VRP 和 Comware 单独作为软件平台线索。SSH/服务标识中明确出现时记录到 OS 候选；仅管理页标题出现时只显示平台线索，OS 仍可未知。仅有 VRP / Comware 时显示“网络设备（具体类型未知）”，不单凭平台名称判断路由还是交换。

### 展示和判定边界

详情、扫描表及导出报告新增 device_vendor、vendor_confidence、vendor_candidates、model_hint、platform_hint。服务标识厂商与 MAC 注册厂商分开显示，避免把网卡供应商或代理网关当成设备品牌。

仅品牌名称不决定设备类型；型号/产品族正则必须有相关品牌或产品标识的上下文。多品牌、多类型证据矛盾时保留候选并降低置信度。通用 OpenSSH、nginx、端口、MAC 前缀和 IP 末位都不能保证设备品牌或 OS。

这里的“产品线索”是公开字符串匹配，不是硬件型号认证。厂商管理页、反向代理、自定义页及版本变化均可能影响结果。未开放可识别服务时仍可能未知；没有对所有型号进行实机认证。

## 2.3 拓扑使用逻辑修正
- 换网段扫描默认仅显示本轮范围，旧资产继续保存；勾选“显示全部已保存网段”查看全量台账。多范围重叠时设备只显示一次。
- “清除拓扑”清除当前资产文件的全部设备和网段，包含手工备注和冲突记录；操作前确认并自动生成同目录备份，备份失败则不清除。可通过“打开资产文件”恢复备份。独立历史报告与防火墙规则不受影响。
- 清除后停止自动刷新，保留扫描输入方便重新扫描；停止按钮也会关闭定时刷新。
- 延时测试、网卡识别、MAC 获取等操作期间保护资产切换，避免后台结果写入其他文件。另存失败恢复原保存路径。
- 本次通过 114 项自动测试，网络识别测试主要使用模拟响应，并非全型号设备实测。
